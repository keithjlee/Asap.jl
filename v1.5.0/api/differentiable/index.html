Differentiable path

The pure functional analysis path: ModelState, extract_state, solve, and compliance.

Asap.ModelState — Type
ModelState{T}

The differentiable state of a model: everything automatic differentiation is allowed to vary, extracted as plain data. Element kernels are pure functions, so evaluating the pipeline on a ModelState involves no mutation anywhere — Zygote (and other AD engines) differentiate it directly, with only two custom rules (sparse construction and the linear solve) supplied by the ChainRules extension.

Fields

  • X::Matrix{T}: node positions as a 3 × n_nodes matrix (column i is node i) — plain arrays differentiate cleanly through every AD engine; static vectors remain internal to the kernels
  • sections::Vector{AbstractSection{T}}: per-ELEMENT sections, indexed like model.elements (elements sharing a section object simply repeat it)

Construct the reference state with extract_state, then produce perturbed states in your objective (e.g. rebuild positions from a design vector, or sections from area variables) — see the gradient tests for patterns.

Loads: nodal loads P are constant data read from the cache. Element-load fixed-end forces are DESIGN-DEPENDENT: the pure path re-evaluates them at the state's positions, sections and end conditions (assemble_Pf), so gradients include the load path (a member's line load scales with its length, self-weight with ρA, condensed end moments with the end springs and EI). Pass loads = :frozen to solve/compliance for the cached, design-constant fixed-end forces instead.

Asap.assemble_K — Method
assemble_K(cache, state) -> SparseMatrixCSC

Pure (non-mutating) assembly of the free×free stiffness matrix from a differentiable ModelState. Identical numerics to assemble_K! — the two paths share every element kernel and the frozen sparsity pattern — verified by parity tests.

source
Asap.assemble_Pf — Method
assemble_Pf(cache, state) -> Vector

The full-space fixed-end force vector Pf evaluated at the design state: every element load applied by the last assemble_loads! (the plain-data FEFTable in cache.fef) is lowered through element_fef_global at the state's node positions, the element's state section, and its end conditions (state.ends when the state carries them, else the model's), then scattered to global DOFs.

Pure and differentiable: one map over the loaded elements of immutable 12-vector kernels and one sparse matvec. With no element loads it returns the cached Pf untouched, so nodal-load-only models pay nothing. Loads on VariableElements enter as the constant cache.fef.static (their internal geometry is not part of the state).

At the model's own state (extract_state(model)) this reproduces the stateful cache.Pf to rounding.

source
Asap.compliance — Method
compliance(model, state; solver = nothing, loads = :design) -> T

External work Fᵀu_free of the pure solve — the canonical smooth stiffness objective, differentiable end-to-end. loads as in solve: with design-dependent loads F itself varies with the design, and the gradient includes that term.

Asap.extract_state — Method
extract_state(model) -> ModelState

The model's current geometry and sections as a differentiable state.

source
Asap.fef_local — Method
fef_local(cache, state) -> Matrix   (12 × n_loads)

The LOCAL condensed fixed-end force vectors q̃ (condensed_fef) of every state-tracked element load at the design state, one column per load, in cache.fef order (cache.fef.elem[j] is load j's element). These are the q̃ terms of the local force recovery f = k·u_local + q̃, e.g. slot 7 is the load's contribution to the end-node axial action. Pure and differentiable.

source
CommonSolve.solve — Method
solve(model, state; solver = nothing, loads = :design) -> Vector

Pure linear solve on a processed model: assemble from the differentiable state, solve, and return the FULL-space displacement vector (inactive and fixed slots zero). Requires process! (or a prior solve!) to have built the cache; nodal loads are taken from the cache as constants, so call assemble_loads! first if loads changed.

loads = :design (default) re-evaluates element-load fixed-end forces at the state (assemble_Pf): a member's line load follows its current length, self-weight its ρA, condensed end moments its end springs and EI. loads = :frozen uses the cached, design-constant Pf instead (the behavior before v1.2: loads fixed at the model's stored geometry).

solver selects the linear-solver backend for the reduced solve (see solve_free); nothing is the built-in CHOLMOD path.

This is the AD entry point: gradients of any scalar of the returned vector with respect to node positions and section properties flow through Zygote with no further ceremony.

Load cases

Several load cases at one design state, one factorization: the plain-data case table and its design-dependent fixed-end forces.

Asap.CaseLoads — Type
CaseLoads{T}

Several load cases of a processed model as plain data, for the pure (differentiable) path: built once by case_loads, consumed by solve(model, state, cl) and compliance(model, state, cl) at any design state.

Column k of every matrix belongs to case names[k]; n is the number of global DOFs (6 × n_nodes).

Fields

  • names::Vector{Symbol}: the case tags, in column order
  • P::Matrix{T}: nodal loads per case (n × n_cases) [force, moment]
  • static::Matrix{T}: fixed-end forces that do not follow the design (element loads on VariableElements) per case [force, moment]
  • F0::Matrix{T}: the frozen load vectors P − Pf per case, with every fixed-end force evaluated at the model's own geometry and sections (what loads = :frozen uses) [force, moment]
  • fef::FEFTable{T}: the element loads of ALL listed cases (frames, quad and triangle shells), in case order: the plain data the design-dependent fixed-end forces are re-evaluated from
  • fcase, scase, tcase::Vector{Int}: the case (column) of each frame, quad-shell and triangle-shell load in fef
  • cscatter, csscatter, ctscatter::SparseMatrixCSC{T,Int}: CASE SCATTERS (n·n_cases × 12·n_frame, × 24·n_quad, × 18·n_tri): the ordinary scatters of fef with each load's rows moved into its case's block, so reshape(cscatter * q, n, n_cases) places every stacked fixed-end vector q in its own case's column

Built from the cache's DOF numbering: rebuild it after process! changes the model's topology or loads.

source
Asap.case_Pf — Method
case_Pf(cl::CaseLoads, state) -> Matrix

The fixed-end forces of every case at the design state (n × n_cases): the design-independent part cl.static plus every element load of each case re-evaluated at the state (frame loads, quad and triangle shell surface loads), each in its case's column. The multi-case form of assemble_Pf; pure and differentiable.

source
Asap.case_loads — Method
case_loads(model; cases = load_cases(model)) -> CaseLoads

The load cases cases of a processed model (process! or solve! first) as a CaseLoads table for the pure path. Each case's loads are assembled once (the same lowering as assemble_loads!(…; case)): nodal loads, frozen fixed-end forces at the model's own state, and the element loads that the pure path re-evaluates per design.

The cache is left EXACTLY as it was (its load vectors, recovery terms and fixed-end-force table are restored), so the single-case pure path and the stateful results are unaffected.

process!(model)
cl = case_loads(model)                        # every case, first-appearance order
cl = case_loads(model; cases = [:dead, :live])
U  = solve(model, extract_state(model), cl)   # n_dof × 2, one factorization
source
Asap.combination_weights — Method
combination_weights(cl::CaseLoads, combo::LoadCombination) -> Vector

The factors of a LoadCombination as a vector λ over the columns of cl (zero for a case the combination does not name), so that U * λ and F * λ are the combination's displacements and loads. A case named in the combination but absent from cl throws an ArgumentError (a misspelled case would otherwise drop silently).

source
Asap.compliance — Method
compliance(model, state, cl::CaseLoads; solver = nothing, loads = :design) -> Vector

The external work Fₖᵀuₖ of every case at the design state (one stiffness factorization for all of them), loads as in solve(model, state, cl).

The compliance of a combination λ is NOT λ ⋅ compliance (it is quadratic in the loads): it is (Fλ)ᵀ(Uλ), the work of the combined load on the combined displacement.

source
Asap.fef_local — Method
fef_local(cl::CaseLoads, state) -> Matrix   (12 × n_frame_loads)

The LOCAL condensed fixed-end force vectors q̃ of every frame element load of the cases at the design state, one column per load in cl.fef order: load j acts on element cl.fef.elem[j] and belongs to case cl.names[cl.fcase[j]]. The multi-case form of fef_local(cache, state): per-case force recovery adds each case's columns to its own element forces (e.g. slot 7, the end-node axial action, to the axial force). Pure and differentiable.

source
CommonSolve.solve — Method
solve(model, state, cl::CaseLoads; solver = nothing, loads = :design) -> Matrix

The pure solve for several load cases at once: one stiffness assembly and one factorization at the design state, one right-hand side per case. Returns the FULL-space displacements, n_dof × n_cases (column k is case cl.names[k]; inactive and fixed slots zero).

loads = :design (default) re-evaluates every case's element loads at the state (case_Pf): frame line and point loads and self-weight, quad and triangle shell surface loads. loads = :frozen uses the loads at the model's own state (cl.F0). Rigid diaphragms are handled as in the single-case solve.

A load combination is a linear combination of the columns: U * λ with λ from combination_weights. Differentiable with Zygote, ForwardDiff, Enzyme and Mooncake.

Internals

The linear-solve seam of the differentiable path (the function AD rules attach to):

Asap.solve_free — Function
solve_free(K, F) -> u_free
solve_free(solver, K, F) -> u_free

Solve the reduced linear system. The AD extension supplies the adjoint (one extra back-substitution on the cached factorization — the classical adjoint method).

The 3-arg form goes through the solver seam (_factorize(solver, K)): solver may be nothing (built-in CHOLMOD), any LinearSolve algorithm (with AsapLinearSolveExt), or a CachedSolver wrapper that reuses one factorization across value/adjoint/tangent passes at the same design. The 2-arg form is the default-solver fast path — kept as its own method (not a forwarder) because Enzyme's imported rules match this exact signature.

source

The plain-data mirror of the applied element loads that assemble_Pf re-evaluates per state:

Asap.FEFTable — Type
FEFTable{T}

Plain-data mirror of the element loads applied by the last assemble_loads!, consumed by the differentiable pure path (assemble_Pf) to re-evaluate fixed-end forces at any design state. Rebuilt by every assemble_loads! call, so it respects the same case selection as P.

Only loads on FrameElements are tracked per state. Loads on VariableElements (whose internal geometry the pure state does not carry) contribute a constant static vector, frozen at the model's stored values.

Fields

  • loads::Vector{Any}: the element-load objects (immutable; only their intensity/position/direction fields are read, never load.element)
  • elem::Vector{Int}: model element index of each load
  • i1, i2::Vector{Int}: start/end node indices (columns of state.X)
  • rollangle::Vector{T}: the element's roll angle [rad]
  • ends::Vector{Any}: the element's EndConditions (overridden per element by state.ends when the state carries them)
  • scatter::SparseMatrixCSC{T,Int}: n_global × 12·n_loads 0/1 map from the stacked per-load global 12-vectors to global DOFs
  • static::Vector{T}: full-space FEF contribution of loads NOT tracked per state (VariableElement loads)
  • sloads, selem, snodes, sscatter: the SHELL surface loads (AreaLoad, SelfWeight on ShellElements), re-evaluated per state: model element index, the 4 node indices (4 × n), and the n_global × 24·n scatter of their global 24-vectors (quadrilaterals)
  • tloads, telem, tnodes, tscatter: the same for TRIANGULAR shells (3 × n node indices, n_global × 18·n scatter)
