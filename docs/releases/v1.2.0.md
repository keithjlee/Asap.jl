# Asap v1.2.0

Design-dependent element loads on the differentiable path.

## Changed (behavior fix)

- **Element-load fixed-end forces now follow the design on the pure path.**
  `solve(model, state)` and `compliance(model, state)` used to read the load
  vector `P − Pf` from the analysis cache, with `Pf` frozen at the model's
  stored geometry, sections and end conditions. Fixed-end forces actually
  depend on all three: a member's line load scales with its length,
  self-weight with ρA, and condensed end moments with the end springs and
  EI. Gradients through the pure path therefore omitted the load path
  entirely. Measured downstream in AsapOptim, compliance gradients were
  wrong by factors of −35 (cantilever length of a Gerber beam), −0.025
  (gridline position of a multistory frame) and −0.008 (area of a member
  with self-weight), all with the wrong sign.

  The pure path now re-evaluates every element load at the state
  ([`assemble_Pf`](@ref)). It agrees exactly with a rebuilt, stateful-solved
  model, and its Zygote and ForwardDiff gradients agree with central
  differences of rebuilt models.

  Semantics under design change: distributed loads are per-unit-length
  intensities (the total follows the current length); point forces/moments
  keep their fractional position; `SelfWeight` follows ρA·L; `:local`
  directions rotate with the member.

  `loads = :frozen` on `solve`/`compliance` restores the previous behavior.
  Models without element loads are unaffected: `assemble_Pf` returns the
  cached vector untouched.

## Added

- `assemble_Pf(cache, state)`: the fixed-end force vector at a design state.
- `fef_local(cache, state)`: per-load local condensed FEF vectors `q̃` (the
  `q̃` of the force recovery `f = k·u_local + q̃`), e.g. for differentiable
  member-force recovery under element loads.
- `condensed_fef`, `element_fef_global`: the per-load pure kernels both the
  stateful and the pure assembly evaluate.
- `AnalysisCache.fef` (`FEFTable`): plain-data mirror of the applied element
  loads, rebuilt by `assemble_loads!` (so it respects its `case` selection).

## Internal

- `fixed_end_forces` and `_rotate12` are non-mutating (immutable `SVector`
  arithmetic), so Zygote differentiates them. Stateful numerics are
  bitwise unchanged (checked across every load type and end condition).
- `SelfWeight` lowers through the quadrature kernel directly instead of
  constructing a `DistributedLoad{T}`, which could not hold a Dual ρA.

## Known limits

- Element loads on `VariableElement`s stay frozen on the pure path (their
  internal geometry is not part of the state).
- Pure-path load cases/combinations remain a follow-on; the pure path uses
  whatever `assemble_loads!` last assembled.
- Reverse-mode cost: each loaded element is one kernel closure. On a
  190-element frame with 80 loaded beams the Zygote compliance gradient
  goes from 110 ms (frozen) to 182 ms, the same per-element cost the
  frame stiffness path already pays. Batching both is a separate project.

Lockstep: AsapOptim 1.2 consumes this (its `OptParams` no longer snapshots
`F`).
