# Asap v1.3.0

Shell elements, wall modelling and rigid diaphragms, and faster reverse-mode gradients for
frames. This release only adds API. Existing models give bitwise-identical results to v1.2.0:
displacements, reactions, element forces, stiffness values, pure-path compliance and ForwardDiff
gradients. Zygote gradients of frame models agree with v1.2.0 to 6e-15 relative, because the frame
kernels are now differentiated by local ForwardDiff rules (see Performance); truss gradients are
bitwise identical. Checked against v1.2.0 on six models covering trusses, a space truss, frames with
every element-load type, releases, semi-rigid ends, spring supports and a `VariableElement`.

## Added

### Shell elements
- `ShellElement`: a 4-node flat shell that mixes freely with frames and trusses.
  - **Membrane:** the Ibrahimbegović–Taylor–Wilson (1990) drilling quad, with two
    complementary Taylor-corrected incompatible modes. It is exact in pure bending on
    rectangles and within about 3% on walls meshed two elements wide. The published element
    is available as `itw_membrane_stiffness(...; enhanced = false)`.
  - **Plate:** MITC4 (Dvorkin–Bathe), free of shear locking from thick to thin plates.
  - The true drilling DOF lets in-plane beams transfer moment into walls.
- `ShellSection(material, t)` and `ShellRigiditySection(A, D, S, ρt)`, the latter with a
  stiffness-modifier constructor (`f11 … v23`) for cracked or effective concrete.
- Accessors: `membrane_rigidity`, `bending_rigidity`, `shear_rigidity`, `drilling_rigidity`,
  `areal_mass`, `thickness`.
- `AreaLoad` (a uniform traction, or a pressure along the normal) and `SelfWeight` on shells,
  lowered to consistent nodal loads.
- `shell_resultants` (N, M, Q in local axes) and `section_cut` (exact integrated forces across
  a cut from element nodal forces, for pier and spandrel design forces).

### Walls and connections
- `mesh_wall`: a structured wall mesh with rectangular openings, guaranteed hard lines, and
  node reuse for cores and frame connections.
- `wall_cut`: pier and spandrel free bodies for `section_cut`.
- `edge_loads`: consistent line tractions, including the drilling end moments.
- `LinkElement`: a zero-length 6-spring connection for precast joints and bearing pads.

### Rigid diaphragms
- `RigidDiaphragm(nodes; master, axis)` and `Model(...; diaphragms)`.
- The constraint is exact, by transformation: K̂ = CᵀKC is applied as a sparse linear map
  of K's nonzeros, so the frozen-pattern refactorization still applies.
- Supported in `solve!`, `solve_cases!` and on the pure path (offsets frozen at the last
  `solve!`).

### Differentiable path
- Shells take part in `solve`/`compliance` on a `ModelState`, with gradients with respect to
  node positions and thickness.
- Shell surface loads are re-evaluated per state: self-weight follows ρt, pressure follows
  area and orientation.
- New extension `AsapShellADExt` (ChainRulesCore + ForwardDiff): reverse rules for the shell
  kernels that use local ForwardDiff Jacobians, about 15× faster than tracing them.

### Results, plotting, AD backends
- `shell_envelope` gives resultant extrema over combinations.
- `ShellGeo` provides plot-ready shell arrays: displacements, resultants, principal forces.
- `nodal_average` smooths element fields to the nodes; `principal_forces` returns principal
  membrane forces.
- `Geo(model)` / `ModelGeo` work on mixed models (they cover the line elements).
- `element_connectivity` is generic over element types, and the `Model` display counts shells,
  links and diaphragms.
- `AsapShellMooncakeExt` and `AsapShellEnzymeExt` make Mooncake and Enzyme (reverse) gradients
  through shells work, by bridging the shell rules (both fail on the kernels natively). All
  backends agree to 1e-16. Warm medians, Julia 1.13, compliance gradient of a shell wall:

  | Elements | Primal | Zygote | Enzyme | Mooncake |
  |---|---|---|---|---|
  | 12 | 0.17 ms | 6.0 ms | 4.1 ms | 10.6 ms |
  | 96 | 1.26 ms | 59.2 ms | 32.5 ms | 97.7 ms |

  Reproduce with `examples/ad/ad_backends_shells.jl`.

### Walkthroughs
`examples/` is now one shared environment (`examples/Project.toml`) with shared figure
generators (`examples/figures.jl`, CairoMakie + kjlMakie; neither is a package dependency).
Every file is shift+enter friendly and also runs top to bottom.
- `examples/analysis/`: planar truss (by hand and by generator), 3D space truss, 2D portal
  frame (diagrams, releases, roll angle), 3D building frame (load cases, drift, combinations,
  envelopes), semi-rigid joints, spring supports and a haunched `VariableElement`.
- `examples/shells/`: wall, slab, frame + coupled wall with diaphragms, precast joints,
  thickness design.
- `examples/optimization/` (with AsapOptim): truss sizing by optimality criteria, shape vs
  size, connection stiffness at a drift limit (implicit differentiation).
- `examples/ad/`: the Enzyme matrix (reverse and forward, every scenario class; see
  `examples/ad/ENZYME_STATUS.md`), the shell AD-backend timings and reverse-mode scaling.
- `examples/reports/`: a Typst report per walkthrough, plus all of them in one document. Each
  walkthrough writes the numbers its report prints (`report_data`), so no number is typed by hand.

### Infrastructure
- `AbstractLineElement` supertype for the two-node elements.
- The analysis layer handles elements with any number of nodes.
- `connectivity(model)` now refuses models that contain surface elements.

## Performance

Reverse-mode (Zygote) gradients of frame models: compliance with respect to every node coordinate,
line loads on every beam (`examples/ad/reverse_scaling.jl`, Julia 1.13, one thread):

| Model | Primal | v1.2 | 1.3 |
|---|---|---|---|
| Frame, 120 elements | 0.4 ms | 62.8 ms | 16.7 ms |
| Frame, 665 elements | 2.9 ms | 435.6 ms | 256.2 ms |

`AsapFrameADExt` (loaded with ChainRulesCore and ForwardDiff) gives the frame stiffness and
element-load kernels reverse rules that evaluate the kernel's own derivative with ForwardDiff, the
pattern of the shell rules. Zygote previously traced each 12×12 kernel scalar by scalar: about 150 µs
per stiffness pullback and 250 µs per element-load pullback, against 0.8 µs and 0.1 µs for the
kernels themselves. Rigid and released end springs are exact limits with zero derivative, as before.
Enzyme and Mooncake differentiate these kernels natively and are unaffected.

The gain shrinks with model size: the pure path's per-element closures index arrays they capture,
and under Zygote each index pulls back into a full-size cotangent, so the remaining cost grows
quadratically. A fix (gather per-element inputs, then `map`) was tried and reverted: it breaks
Enzyme, which mishandles a type-unstable `map` over abstractly typed arrays and in forward mode
returned wrong derivatives without an error.

## Changed
- `Model` gained a `diaphragms` field (before `cache`). Code that reads fields by name is
  unaffected.
- `FEFTable` gained shell-load fields at the end.

## Fixed
- `SpaceFrame` and `Frame` docstrings: the load goes on every unsupported node (both layers), `:x`/`:y`
  support the two edges at the ends of the X/Y span, and the joist count includes the column lines.
- The two Enzyme extensions no longer evaluate rules while a dependent package precompiles.
  On Julia 1.12, loading `AsapShellEnzymeExt` failed with "Evaluation into the closed module
  `AsapEnzymeExt` breaks incremental compilation".

## Downstream
- AsapOptim: `ThicknessVariable` and `shell_volume`, shell-aware `OptParams`, and rigid
  diaphragms in `solve_structure`.
- `solution_tangents` (implicit differentiation) supports shells: thickness, shell-node
  geometry, design-dependent shell loads, and rigid diaphragms.
